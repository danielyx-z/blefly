# Sideloading BLEFly on iOS with SideStore

The app is built on GitHub's macOS runners and shipped as an **unsigned `.ipa`**.
SideStore re-signs it with your own Apple ID, so no Apple Developer Program
membership (99$/yr) is needed — a free Apple ID works.

## 1. Build it

The workflow lives at `.github/workflows/ios-unsigned-ipa.yml`.

Push to `master`, then on GitHub go to **Actions → Build unsigned iOS IPA →
Run workflow**. It runs typecheck + lint, generates the native `ios/` project
with `expo prebuild`, builds with `CODE_SIGNING_ALLOWED=NO`, and produces:

- **Artifact** `BLEFly-unsigned-ipa` — zip containing `BLEFly-unsigned.ipa`
  (every build)
- **Release** `ios-<n>` — the raw `.ipa` on a permanent URL
  (manual runs only, handy for SideStore's "Install from URL")

Build time is roughly 15–25 min on a cold CocoaPods cache.

Why CI and not local: iOS binaries require Xcode, which only runs on macOS.
There is no way to produce an `.ipa` on Linux/Windows.

## 2. Get it onto the phone

1. Download `BLEFly-unsigned.ipa` on the iPhone (release page link in Safari,
   or AirDrop / Files).
2. Open **SideStore → My Apps → +** and pick the `.ipa`.
3. SideStore signs it with your Apple ID and installs it.
4. First launch: **Settings → General → VPN & Device Management → trust** your
   developer certificate.
5. Accept the Bluetooth permission prompt on first connect.

## 3. Keep it alive

Free Apple IDs get **7-day provisioning** and a **3-app limit**. SideStore
refreshes them automatically in the background, but only while its WireGuard
VPN profile is active and the phone can reach a SideStore pairing server
(Loopback/House-party setup). If the app stops launching after a week, open
SideStore and refresh.

## Things that will bite

- **iOS 16.4 minimum.** Expo SDK 57 / RN 0.86 sets the deployment target to
  16.4, so the phone must be on 16.4 or newer.
- **Bundle ID is rewritten** by SideStore (`com.<hash>.blefly`). That's expected
  and harmless — the BLE UUIDs and device name in `src/utils/protocol.ts` are
  what identify the robot, not the app identity.
- **No entitlements.** `ios/BLEFlyController/BLEFlyController.entitlements` is
  empty, which is exactly what SideStore wants. `react-native-ble-plx` only
  needs the `NSBluetoothAlwaysUsageDescription` Info.plist strings, already set
  via the plugin in `app.json`.
- **Don't commit `ios/`.** It's generated by `expo prebuild` (CNG) and already
  gitignored. Change native config in `app.json` instead.

## If you ever get a Mac

```bash
npx expo run:ios --configuration Release --device
```

signs and installs straight to the phone with Xcode's local signing, no
SideStore involved.
